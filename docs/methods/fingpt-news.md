# FinGPT news sentiment research and paper trading

## Scope

The FinGPT integration accepts sentiment generated by any compatible model,
including the public FinGPT sentiment adapter, a locally trained LoRA adapter,
or an external classifier. Model weights and raw news are not bundled.

The implementation consolidates the previous ETH pretrained-LoRA backtest,
ETH sentiment-SFT validation/test workflow, ten-coin asset/market strategy
sweep, and daily FinGPT paper trader into one package. Historical scripts remain
useful provenance references; new users have a stable CLI, typed configuration,
synthetic fixture, and common output contract.

## Install

Offline research uses core dependencies only:

```bash
python -m pip install -e .
```

Install optional capabilities separately:

```bash
# Local transformers/PEFT inference
python -m pip install -e ".[news]"

# RSS/Google News, public prices, and OKX adapters
python -m pip install -e ".[fingpt-live,runtime]"
```

These commands install from the current checkout. PyPI installation applies
only after an official `quant-bench` release is published.

## Offline quickstart

```bash
quant-bench fingpt init --workspace ./qb-workspace

CONFIG=./qb-workspace/methods/fingpt_news/research/config.yaml
quant-bench fingpt validate --config "$CONFIG"
quant-bench fingpt backtest \
  --config "$CONFIG" \
  --output ./qb-workspace/runs/fingpt-smoke
```

`init` exports two-symbol synthetic prices, separate validation and test
sentiment, and an editable config. No exchange, model hub, news endpoint, or
account is contacted.

## Input contracts

Price CSV requires one unique positive close per symbol and date:

```text
date,symbol,close
```

Sentiment CSV requires:

```text
date,symbol
```

and one score representation:

```text
article_score
prob_positive,prob_negative
model_score
```

Optional fields include `datetime`, `news_id`, `bucket`, `source`,
`relevance_weight`, `model_label`, and `true_label`. `bucket` is `asset` or
`market`. Asset rows must use a configured symbol. Market rows are replicated
across the configured universe during daily aggregation.

Scores must be finite and within `[-1, 1]`. Prices must have at least two common
dates across every configured symbol. Validation and test windows are half-open
and cannot overlap.

## Parameter selection

The config exposes two grids:

- aggregation: asset/market top-N, minimum absolute article score, and score
  power;
- signals: strategy variant, threshold, fixed alpha, and adaptive alpha
  parameters.

Supported variants:

```text
asset_only
market_only
hybrid_fixed
hybrid_adaptive
```

Adaptive aggregation uses:

```text
alpha = clip(asset_weight_sum / (asset_weight_sum + k), min_alpha, max_alpha)
final_score = alpha * asset_score + (1 - alpha) * market_beta * market_score
```

The global configuration is selected exclusively from the validation window.
The test window is evaluated once with the frozen configuration. The manifest
and `chosen_config.json` record `test_metrics_used_for_selection: false`.

Selection objectives are `sharpe`, `total_return`, `calmar`, and
`excess_total_return`. Coverage guards enforce minimum trades, signal days, and
classified news. When no trial passes, the run records
`selection_status: coverage_fallback` instead of silently claiming a validated
configuration.

Guarded per-symbol thresholds reuse the selected aggregation and signal
variant. Symbols that fail coverage inherit the global threshold.

## Backtest semantics

Every symbol owns an independent capital bucket. Capital is never redistributed
between symbols.

```text
positive -> target long
negative -> target flat
neutral  -> retain the prior target
```

The target is delayed by `signal_lag_days`, whose minimum is one. A news score
on day T therefore cannot earn the close-to-close return already realized on
day T. Entry and exit turnover pay configured fees and slippage.

Outputs include single-symbol and portfolio return, volatility, Sharpe,
Sortino, Calmar, drawdown, win rate, profit factor, exposure, turnover, costs,
trade count, news coverage, and buy-and-hold comparison.

## Paper and scheduled execution

Offline fixture paper cycle:

```bash
quant-bench fingpt paper-dry-run --workspace ./qb-workspace
```

For network paper mode, export and review the packaged YAML, set
`runtime.dry_run: false` and `trade.mode: paper_spot`, then invoke the module
with `--allow-network`. This enables configured news collection, model services,
and unauthenticated OKX ticker reads. It does not create an account executor.

OKX demo/live modes require all of the following:

1. an OKX trade mode in reviewed configuration;
2. credentials from the configured environment variable names;
3. `--allow-network`;
4. `--execute-orders`;
5. `DEMO_ORDERS` for flag `1`, or `LIVE_ORDERS` for live mode.

Inline YAML credentials are rejected. Account reconciliation defaults to
`false` and is independent from ordinary strategy-owned quantity tracking.

## Migrated and retained capabilities

The reusable engine covers the previous ETH and ten-coin long/flat backtests,
validation threshold tuning, asset/market variants, adaptive alpha, global and
per-coin thresholds, fees, independent buckets, label distributions,
classification evaluation, and result plotting inputs. Existing live support
retains prompt caching, isolated inference workers, restart state, news
attribution, audit CSVs, and dashboard manifests.

The old account-alignment script is not exposed as a normal library command.
Its behavior can place account orders and belongs under a separately reviewed
operator workflow. Historical reconstruction is handled non-destructively by
the offline research command using user-supplied sentiment and price files.

## Publication boundary

Safe to publish:

- package source and typed configs;
- synthetic fixtures and tests;
- checksum/data-quality manifests;
- parameter spaces and metric definitions;
- documentation and license notices.

Keep local:

- raw CCData, RSS, Google News, StockTwits, or CryptoPanic content;
- model weights, LoRA adapters, tokenizer snapshots, and prompt caches;
- account state, orders, fills, news attribution containing full text, and
  runtime logs;
- results that have not passed disclosure and data-license review.

The file `per_coin_params_sentiment_sft_2025.csv` is retained as a legacy
experiment recipe. The safe live template uses `per_coin_params_default.csv`,
which contains uniform general-purpose starting values and no performance
claims.
